# CPI Config Manager

A self-hosted web tool for SAP Cloud Platform Integration (SAP CPI) administrators to export, import, compare, and update iflow configuration parameters across multiple tenant environments.

---

## Overview

CPI Config Manager solves the day-to-day problem of keeping iflow configuration parameters in sync across CPI tenants (development, QA, staging, production). Instead of manually copying values through the SAP Integration Suite UI, you can:

- Export all iflow parameters from a tenant to versioned YAML files
- Import and apply those files to a different tenant with a diff preview
- Compare parameter values between two tenants side-by-side
- Deploy updated iflows directly from the UI

All operations run in the background — you can navigate freely between pages without interrupting a running export, import, or comparison.

---

## Features

| Feature | Description |
|---|---|
| Dashboard | Lists all iflows with live runtime status for a selected tenant |
| Export | Exports iflow config parameters to YAML or `.properties` files, organised by package |
| Import / Update | Previews a diff of file values vs live CPI values, then applies selected changes |
| Compare Environments | Side-by-side parameter diff between two tenants; downloadable as CSV or HTML |
| Background operations | Export, Apply, and Compare tasks survive page navigation |
| Multi-tenant | Unlimited tenants, each with its own OAuth credentials and environment label |
| CSRF handling | Automatically fetches and refreshes SAP OData CSRF tokens before mutations |
| File upload | Drag-and-drop YAML / ZIP upload into the import directory from the browser |

## Architecture

```
cpi-config-manager/
├── backend/                  Express.js API server (Node.js 18+)
│   ├── src/
│   │   ├── index.js          Entry point, serves built frontend as static files
│   │   ├── routes/           REST routes: export, import, deploy, compare, ...
│   │   └── services/
│   │       ├── cpiService.js SAP CPI OData API client (configs, packages, deploy)
│   │       ├── tokenService.js OAuth2 client_credentials token cache
│   │       └── dataService.js  JSON file read/write helpers
│   └── data/                 Runtime data (gitignored except .gitkeep)
│       ├── tenants.json      Tenant registry with OAuth credentials (NEVER commit)
│       ├── settings.json     App settings (auto-created on first run)
│       ├── exports/          Exported YAML files, organised by env/package
│       └── imports/          YAML files staged for import/apply
└── frontend/                 React 18 + Ant Design 5 + Vite
    └── src/
        ├── pages/            Dashboard, Export, Import, Compare, Settings
        ├── store/index.js    Zustand global state (background task status)
        └── api/index.js      Axios API client
```

The backend builds the frontend into `backend/public/` and serves it at the root. There is a single port (`3002` by default) for both the API and the UI.

## Prerequisites

- **Node.js** 18 or later
- A SAP CPI tenant with an OAuth service key (client credentials grant)
  - Go to **SAP BTP Cockpit** > your subaccount > **Service Instances** > your CPI service instance > **Service Keys**
  - Note the `url` (host), `clientid`, `clientsecret`, and `tokenurl` values

## Quick Start

```bash
# 1. Clone the repository
git clone <repo-url>
cd cpi-config-manager

# 2. Install backend dependencies
cd backend
npm install

# 3. Install and build the frontend
cd ../frontend
npm install
npm run build          # outputs to ../backend/public/

# 4. Start the server
cd ../backend
node src/index.js
# CPI Config Manager running on http://localhost:3002
```

Open `http://localhost:3002` in your browser. The backend auto-creates `settings.json` and `environments.json` in `backend/data/` on first run.

For development with hot-reload:

```bash
# Terminal 1 — backend (auto-restarts on changes)
cd backend
npm run dev

# Terminal 2 — frontend dev server
cd frontend
npm run dev            # http://localhost:5173 (proxies API to :3002)
```

## Tenant Setup

Tenant credentials are stored in `backend/data/tenants.json`. This file is gitignored because it contains OAuth client secrets. Use the provided example as a template:

```bash
cp backend/data/tenants.example.json backend/data/tenants.json
```

Edit `tenants.json` with your real values, or use the **Settings > Tenants** page in the UI to add tenants through a form (recommended).

### Tenant JSON shape

```json
[
  {
    "id": "a unique UUID (generated by the UI)",
    "name": "Dev Tenant",
    "environment": "dev",
    "host": "https://<subdomain>.it-accd003.cfapps.<region>.hana.ondemand.com",
    "auth": {
      "clientId": "sb-your-client-id!...",
      "clientSecret": "your-client-secret",
      "tokenUrl": "https://<subdomain>.authentication.<region>.hana.ondemand.com/oauth/token",
      "token": null
    }
  }
]
```

> **Security note:** `tenants.json` is listed in `.gitignore`. Double-check it is not staged before any `git commit`. The `token` field is populated automatically at runtime and rotated before expiry.

## Usage

### Dashboard

Select a tenant from the dropdown. The table lists all iflows with their runtime status (Started, Error, etc.), package, version, and deployment info. Use the search and package filter to narrow the list. Click **Reload** to refresh the runtime status.

### Export

1. Select a tenant.
2. Optionally filter by package or search by name.
3. Select specific iflows, or leave all unselected to export everything.
4. Choose **Format** (YAML or Properties) and **Folder structure** (per-package or flat).
5. Click **Export**. Files are written to `backend/data/exports/<env>/<package>/<iflowId>.yaml`.

The export runs in the background. Navigate away freely — a spinner appears on the Export nav item until it completes. Results and any errors are shown when you return.

### Import / Update

**Uploading files**

Drag-and-drop YAML, `.properties`, or ZIP files onto the upload area. Files are extracted into `backend/data/imports/<env>/`.

**Applying updates**

1. Select a target tenant.
2. Select the iflows whose import files you want to apply (files-with-matches are pre-selected).
3. Click **Preview Changes** to see a diff of file values vs the live CPI values. The table automatically filters to iflows with detected changes.
4. Review the diff, then click **Apply Updates**.

The apply runs in the background via the SAP CPI OData Management API. Navigate away freely. Results (updated count, errors, parameter-level detail) are shown when you return.

**Only update changed values** checkbox (default: on) skips parameters whose value already matches the file.

### Compare Environments

1. Select a **Source** tenant (the reference) and a **Target** tenant (the one to verify).
2. Click **Compare**. All iflows are fetched from both tenants and parameter values are diffed.

The comparison runs in the background. A spinner on the Compare Envs nav item indicates progress. Results include a summary row (total / identical / different / only-in-source / only-in-target) and a searchable, filterable table. Expand any iflow row to see the per-parameter diff. Download as CSV or HTML report.

### Settings

| Section | Description |
|---|---|
| Tenants | Add, edit, or delete tenant configurations. Tests the OAuth token on save. |
| General | App name, theme (light/dark), default page size |

## YAML Config File Format

Exported YAML files have the following structure:

```yaml
metadata:
  iflowId: com.example.mypackage.MyIflow
  iflowName: My Integration Flow
  packageId: MyPackage
  exportedAt: '2026-11-16T09:00:00.000Z'
parameters:
  EndpointUrl:
    value: https://api.example.com/v1
    dataType: xsd:string
  MaxRetries:
    value: '3'
    dataType: xsd:integer
  EnableLogging:
    value: 'true'
    dataType: xsd:boolean
```

The `dataType` field is read from the live CPI API during export and sent back verbatim during import. Common values: `xsd:string`, `xsd:integer`, `xsd:boolean`.

Legacy exports that store parameters as plain strings (no `dataType`) are still supported on import — the dataType is resolved from the live CPI API at apply time.

## API Reference

All endpoints are prefixed with `/api`.

| Method | Path | Description |
|---|---|---|
| `GET` | `/api/health` | Health check |
| `GET` | `/api/tenants` | List tenants |
| `POST` | `/api/tenants` | Add a tenant |
| `PUT` | `/api/tenants/:id` | Update a tenant |
| `DELETE` | `/api/tenants/:id` | Delete a tenant |
| `GET` | `/api/iflows?tenantId=` | List all iflows (with runtime status) |
| `GET` | `/api/packages?tenantId=` | List packages |
| `POST` | `/api/export` | Export configs to files |
| `GET` | `/api/export/inventory?env=` | List exported files for an env |
| `DELETE` | `/api/export/folder?env=` | Clear exported files for an env |
| `POST` | `/api/import/preview` | Preview import diff (no writes) |
| `POST` | `/api/import/apply` | Apply import files to CPI |
| `POST` | `/api/import/upload` | Upload YAML/ZIP to import directory |
| `DELETE` | `/api/import/folder?env=` | Clear import files for an env |
| `POST` | `/api/deploy` | Deploy one or more iflows |
| `GET` | `/api/compare` | Compare two tenants |
| `GET` | `/api/settings` | Get app settings |
| `PATCH` | `/api/settings` | Update app settings |

## Security Notes

- `backend/data/tenants.json` stores OAuth client secrets in plaintext. Keep this file local and out of version control.
- The server binds to `0.0.0.0:3002`. In production, place it behind a reverse proxy with authentication (nginx, SAP Cloud Connector, etc.) — it has no built-in login.
- CSRF tokens are fetched from the CPI API before every mutating call and are cached per-tenant for 24 minutes with automatic retry on 403.
